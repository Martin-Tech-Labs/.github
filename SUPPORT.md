# Support

This guide applies to repositories in this organization unless a repository
provides its own support instructions.

## Questions and troubleshooting

Start with the affected repository's README, documentation, and existing issues.
Your question may already have an answer or a documented workaround.

Use the repository's Discussions tab for questions when it is available.
Otherwise, open an issue in the affected repository using the appropriate
template, if provided.

To help others understand the problem, include:

- What you are trying to achieve.
- The version or commit you are using and your operating system.
- What you expected to happen and what actually happened.
- Relevant error messages, reproduction steps, and what you have already tried.

Share minimal examples and sanitized logs. Do not include credentials,
encryption keys, private conversations, personal information, or other sensitive
content in public reports.

## Bug reports

Search existing issues before reporting a bug. If no issue matches, open a new
issue in the affected repository using its Bug template, if available. Include
reproduction steps, expected and actual behavior, and enough environment details
to investigate.

If you encounter an existing bug, add useful reproduction details to that issue
rather than opening a duplicate.

## Feature requests

Use the User Story template, if available, to describe who would benefit, what
capability is needed, and why it matters. Include observable acceptance criteria
where possible. For an idea that needs discussion first, use Discussions when
available or open an issue explaining the problem you want to solve.

## Security concerns

Do not report suspected vulnerabilities in public issues or discussions. Follow
the affected repository's security policy, shown under **Security → Policy**.
The organization's default policy is [SECURITY.md](SECURITY.md).

## Contributing a fix

If you would like to help, follow the affected repository's contribution guide.
The organization's default guide is [CONTRIBUTING.md](CONTRIBUTING.md).
Coordinate substantial changes with maintainers before starting implementation.

## Response expectations

Support is provided as maintainer and community availability allows. There is no
guaranteed response time or resolution deadline. Keep follow-ups respectful and
add new information when it helps move the discussion forward.
